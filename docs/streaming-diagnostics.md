# 流式输出链路诊断

## 固定复现实验

固定问题：

> 请详细介绍光刻工艺从晶圆准备到显影检查的完整流程、关键控制参数和常见缺陷，分章节回答

修复前在 `20260720-7` 上记录到 2996 个 `answer_delta`、5380 个正文字符。正文首分片在 15.525 秒到达，正文阶段最大服务端分片间隔为 163 ms，最终流式字符与结果字符完全一致。该数据排除了正文阶段模型长停顿和服务端丢分片，主要瓶颈是浏览器以 24 至 32 ms 间隔反复解析并替换完整 Markdown DOM，同时每帧最多只消费 16 个字符。

## 分段指标

- 模型流：`first_content_ms`、`max_content_gap_ms`、`content_delta_count`、`content_chars`、`stream_duration_ms`。
- 服务端：首个答案入队、最大入队间隔、最大队列等待、最大 SSE yield 间隔、答案事件数和字符数。
- 浏览器：读取分片数、最大读取间隔、最大缓冲积压、渲染帧数、最大和总渲染耗时、后台恢复次数、最终一致性。
- metadata 日志只保存上述聚合数值，不保存回答正文。浏览器遥测接口使用严格字段校验，额外字段会被拒绝。

## 修复策略

浏览器缓冲改用游标消费，避免反复移动整个字符数组。活动流按积压量自适应消费，最终结果按有界帧数快速排空；Markdown 重绘最低间隔为 72 ms，并根据上一帧耗时提高间隔。标签页恢复可见时立即补绘。连续 1.5 秒没有新答案分片时仅显示“模型继续生成中”，不伪造输出。

最终正文仍以服务端 `result.answer` 为准。流式缓冲需要满足突发长文本不丢字、不重复，规范化后的最终正文可以替换不兼容的临时流。
