# 值班聊天的 Skill 选择与执行

**状态：首批光刻 Cpk 工作流已完成本地验收。** 见[实施与验收报告](reports/duty-chat-skill-execution.md)。 面向 PE / EE 值班助手，支持工程师手动指定和助手按意图选择。首批选择现有光刻 Cpk 排查 Skill，在本地用合成数据、模拟部门身份和脚本化模型夹具验收。

## 触发规则

| 入口 | 行为 |
| --- | --- |
| 工程师手动指定 | 本次请求优先使用指定 Skill。发送前可以移除选择。缺少必填参数时明确追问，权限、启用状态或工具依赖不满足时明确说明原因。 |
| 助手按意图选择 | 用户未指定时，助手可从当前身份有权运行的候选中返回一个 Skill。服务端核对意图、适用范围、授权和运行参数，再决定是否执行。 |
| 普通聊天 | 没有适用 Skill 或模型返回无效候选时，继续现有意图路由和工具路径。多个合理候选无法区分时，可以请工程师选择。解释 Cpk 概念等无需查数的提问继续走知识问答。 |

Skill 按请求选择。若上一轮正在补齐已选 Skill 的参数，下一轮仅在用户确实在回答该追问时延续，并重新校验权限。用户变更任务或重新指定时按本次输入处理。手动选择、自动选择和普通聊天共用同一套服务端授权规则。

## 开发清单

- [x] **明确请求与响应契约。** 在聊天入口支持一个可选的 Skill 标识。同步和流式请求使用相同的选择、校验与错误处理。回答或进度显示实际采用的 Skill 及版本，方便工程师核对。
- [x] **接入手动选择。** 在聊天区提供可见、可移除的 Skill 选择。复用能力目录，只展示有权发现的条目并标明依赖状态。服务端根据可信身份验证标识、启用状态、版本、受控工作流和所需工具。
- [x] **接入按意图选择。** 复用现有意图与业务范围判断，形成当前身份有权执行的精简候选。若由模型参与选择，使用有界结构化输出，候选只能指向当前清单中的 Skill。服务端检查模型返回值，处理无匹配、歧义和无效选择。
- [x] **连接工作流和执行权限。** 复用现有 Skill 装配、光刻 Cpk 工作流及 Dispatcher。解析并固定本次运行的 Skill 和工作流版本，依赖工具仍按当前主体权限及预算执行。运行前和工具调用时检查撤权，资料和说明按访问范围装配。用户输入只用于提供业务参数。
- [x] **处理澄清、重试和会话。** 缺时间、制程等必填参数时只追问缺项，具备参数后才调用工具。保留现有消息去重、会话归属、取消与流式事件语义。会话记录可查看实际选择方式、Skill 版本及结果引用。
- [x] **完成本地端到端验收。** 用合成制造数据和模拟角色覆盖下表，验证页面、同步 HTTP、流式聊天及会话回读。原生 Windows 可以复现，按仓库测试策略执行相关链路和阶段门。

## 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 手动优先 | 工程师选中光刻 Cpk 排查后，模型即使建议其他候选也不覆盖选择。答复给出查询范围、数据、来源和限制。 |
| 自动命中 | 工程师直接提出具体光刻 Cpk 排查请求。系统从获准候选中选出正确 Skill，通过受控工具流程返回可核对的结果。 |
| 普通聊天 | 概念解释或无匹配问题继续走原有流程。模型给出不存在或未授权的 Skill 时，不加载内容或执行相关工具。 |
| 缺少参数 | 缺设备、制程或时间时，按所选工作流的实际必填项追问。补齐后按该轮确认范围执行。 |
| 无权限、缺依赖及撤权 | 手动伪造标识、跨部门执行、依赖不可用或停用后继续都受到服务端检查。撤权后的新调用被拒绝，受限资料和工具结果不得进入该轮模型上下文。 |
| 同步、流式与历史兼容 | 两个入口对同一输入执行一致的选择和授权规则。重试不重复执行已成功的工作流，旧会话以及普通聊天仍可正常读取和使用。 |

交付物包括聊天选择入口、服务端选择和执行链路、隔离的本地验收夹具及验收报告。公司环境接入及正式身份授权沿用 [Issue #3](https://github.com/MrJoker06/FAB-Copilot/issues/3)，本任务使用本地模拟。
