# 开门七件事：PE / EE 开班检查与交接

**本地首期已验收。** 让值班工程师按班次查看待处理批次、异常指标和上一班未结事项，能从摘要点到对应报表或记录。

## 参考与首版范围

成功大学刊登的台积电 F14A 制程整合实习心得，将班初例行工作概括为七类。这是实习所在制程整合单位的公开实例。项目中的检查项、班次和异常口径由实际岗位需求确定，PE 与 EE 可使用不同清单。[成功大学《学务通讯》第 233 期](https://stud2.adm.ncku.edu.tw/Newsletter/Data/202511/114.11.pdf)

| 公开实例 | 本地可模拟的数据 |
| --- | --- |
| Hold Lot | 暂挂批次、暂挂原因和待确认事项 |
| 工程备注与批次处理 | 工程交接记录、特殊处理要求和未完成事项 |
| 重点 Lot | 重点批次当前站点、状态与更新时间 |
| CP 良率 | 晶圆探针测试良率趋势及异常批次 |
| WAT | 电性量测指标偏移或超规 |
| Inline 趋势 | 膜厚、关键尺寸等制程量测趋势 |
| 客户相关事项 | 合成的待跟进条目及状态 |

上述七类作为候选。首版建议用暂挂或重点 Lot、制程量测异常、设备报警与未结交接事项验证通用流程。先复用现有基础报表、Lot 共性分析和 SOP 与历史案例入口，数据通过已有具名 Tool 或只读模拟来源提供。当前全部使用原生 Windows、本地合成数据和模拟身份。

## 开发清单

- [x] **定义开班模板。** 明确检查项的岗位或部门、班次窗口、数据来源、判定口径和明细入口。准备一份 PE 样例和一份 EE 样例。
- [x] **准备模拟来源。** 让样例覆盖跨午夜班次、上一班未结项、新增异常、零异常、缺数据及来源失败。每项都能核对对象、数量、来源、查询窗口和更新时间。
- [x] **接入值班工作区。** 支持工程师主动打开开班清单，按项查看摘要和跳转明细。异常、已检查且无异常、数据不足与读取失败需要有不同状态。上一班未结项显示来源和人工跟进信息。
- [x] **连接值班助手。** 工程师可把选中的检查结果带入会话，助手按实际数据说明异常、范围与限制。若开班检查需封装为 Skill，复用[值班聊天的 Skill 选择与执行](duty-chat-skill-execution-plan.md)。工程师负责生产处置和交接确认。
- [x] **做本地验收。** 用模拟 PE / EE 身份走完查看清单、打开报表或 Lot 详情、带结果问助手和查看未结项的流程。覆盖岗位差异、跨班次边界、部门可见性以及来源异常。

## 通过标准

| 场景 | 通过条件 |
| --- | --- |
| 开班查看 | 显示本岗位、本班次适用的检查项。每项都能追溯到数据或来源状态。 |
| 异常与交接 | 指标或批次异常能打开对应明细。上一班未结事项和本班新增事项可区分。 |
| 数据不完整 | 单项无数据、来源失败或记录过期时，其他检查仍可查看。摘要保留各项限制。 |
| 权限与会话 | 受限检查及其详情按当前身份校验。助手使用获准且可追溯的检查结果，标明班次、来源与限制。 |

交付开班样例模板、合成数据、值班入口及本地验收记录。公司 MES、报表和交接数据的接入条件待内网阶段核对。

## 实施编号与追溯

对应 GitHub Issue #4。基线为 PE / EE 分支关闭 #3 后的提交 `ffddc79`。样例以固定 UTC+08:00 的 08:00/20:00 切换，夜班跨午夜，生产班次以公司定义为准。检查单和明细共用服务端岗位校验。传入聊天的是合成记录引用，服务端重新查项，避免将客户端复制的摘要作为可信数据。
