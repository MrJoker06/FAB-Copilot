## 1. 重审结论

保留“有界模型视图 + 同次调用快照 + 受控回读”的方向，但旧稿不能直接作为执行依据。

| 旧稿需要修订之处 | 本版结论 |
| --- | --- |
| 将当前 Loop 一概视为已有按行投影 | 默认 Dispatcher Loop 直接序列化 `result.data`；必须覆盖该真实路径，不能只改旧 handler 或投影函数 |
| “完整结果”容易被理解为来源全部数据 | 只保存本次权限过滤、执行限行后获准采用的完整结果，不能恢复来源未返回或被排除的数据 |
| 回读直接套用业务工具预算 | 共享总调用上限，但不参与业务证据计数、重复查询判断或无进展重置；综合阶段须有明确授权 |
| Ready 增加一个工具名即可回读 | 需要有限的读取、接回响应、最终提交协议，并控制实际模型请求次数、输出额度与截止时间 |
| “Run 累计 24 KiB”含义不清 | 基础视图上限按每次实际模型请求检查；读取次数、响应总字节及存储额度按 Run 累计，不重新发放 |
| 只缩短工具消息 | 同时检查 Ready 嵌入结果、来源摘要、派生报告及保留历史工具消息，防止其他入口绕过 |
| 回读失败与校验失败混用 | 展示/访问失败不改写业务证据评估；MOD-031 的 `check_failed` 仍直接确定性降级，不再调用模型或读取工具 |
| 默认存在统一 Run 关闭接口 | 当前 `AgentRun` 没有 close/context 协议；需要补实际宿主生命周期接缝，不能依赖垃圾回收 |

目标是减少模型接收的工具结果内容，并允许按需补读。首期不承诺降低全进程内存峰值、使整个请求适配任意模型上下文，或提高真实量化模型准确率。

## 2. 标准依据与当前事实

### 2.1 通用约定与项目选择

沿用 MOD-030 的单一 Tool 描述源、输入/输出 Schema 与实际执行绑定，运行时注册视图由该描述源生成。标准不要求所有工具都属于某个 Skill，也不规定本项必须使用 MCP、独立服务或特定目录。

回读是 Runtime 提供的辅助执行能力，不是新的制造业务能力。沿用现有每 Run 注册与 Dispatcher 接缝，区分业务依赖和运行时附加能力；不修改默认 21 项业务工具及 `submit_analysis` 的名称、描述和输入 Schema，不要求 Skill 新增私有文件目录或必填字段。

Deep Agents 仅作为机制参考。本轮核对固定版本 `f2a6e02dc8e2dcb05885c5133b94102ccc79b794`：

- [FilesystemMiddleware](https://github.com/langchain-ai/deepagents/blob/f2a6e02dc8e2dcb05885c5133b94102ccc79b794/libs/deepagents/deepagents/middleware/filesystem.py)：大消息阈值默认参数为 20,000 token，按约 4 字符/token 估算。
- [消息卸载实现](https://github.com/langchain-ai/deepagents/blob/f2a6e02dc8e2dcb05885c5133b94102ccc79b794/libs/deepagents/deepagents/middleware/_message_eviction.py)：保存正文，生成头尾预览；保存失败可由调用方保留原消息。
- [StateBackend](https://github.com/langchain-ai/deepagents/blob/f2a6e02dc8e2dcb05885c5133b94102ccc79b794/libs/deepagents/deepagents/backends/state.py)：文件内容进入会话状态，不等于独立落盘或减少 Checkpoint 大小。

借鉴卸载与回读思路，不引入该 SDK/LangGraph，不照搬阈值，不开放通用 `read_file`，也不在写入失败后回塞无限大原文。

### 2.2 基线中的执行差异

| 当前实现 | 对方案的影响 |
| --- | --- |
| `core/tool_result_projection.py` 只对已知工具列表按行裁剪，保留异常优先排序；未知工具或超长单字段可能不裁剪 | 保留业务排序，再按字节约束；单行与未知工具同样受限 |
| `execution/loop_tool_round.py` 的旧 handler 路径使用 `prompt_content`；`execution/loop_dispatch.py` 的默认路径直接生成工具消息 | 两条真实路径均需验收；关闭功能时保持各自旧行为 |
| `execution/ready_result_policy.py` 会过滤知识结果并按执行行数上限采用结果 | 这是执行边界，不是纯展示裁剪；快照不能恢复被排除的数据 |
| `execution/tool_result_bridge.py` 生成原始 `source_ref` 和观察记录 | 回读沿用原来源身份，不生成第二份独立观察 |
| `synthesis/ready.py` 主要围绕最终提交；`stages/model.py` 的通用知识路径不开放工具 | Ready 需有限回读协议；通用知识首期继续只读摘要，不增加工具 |
| `ToolLoopGuard` 在强制综合时拒绝业务调用，结果记录会影响进展判断 | 不能直接将读取当作业务查询；需要实际执行边界上的辅助调用授权 |
| `application.py` 的 `AgentRun` 无显式关闭接口 | 需要宿主资源作用域，覆盖成功、异常、取消与提前退出 |

## 3. 首期完整流程

1. 默认关闭，显式启用；策略由宿主在 Run 开始时固定，通过实际应用入口生效。Thinking 下拉框与档位设置不在本项范围。
2. 原业务工具完成权限检查、来源调用、过滤和执行结果采用；未授权字段不得进入快照。
3. 同一份采用结果进入原有证据链一次。业务摘要保留异常优先等规则，另外受模型可见字节上限约束。
4. 有内容被展示省略且本路径允许回读时，按额度保存该次调用的快照。完整写入且可读后才发布随机引用，不暴露宿主路径。
5. 允许的诊断综合阶段可读取引用片段或直接最终提交；读取不再次查询业务来源，不重新评估为另一份证据。
6. 每次实际模型请求发送前核对所有 Tool 派生视图与保留的读取响应；无法构造正确且有界的请求时，停止发送并明确降级。
7. 成功、失败、取消、超时及提前返回均关闭资源、使引用失效并清理正常生命周期内的临时文件。

关闭时保持既有行为，不借本项顺带统一默认 Loop 的旧投影。启用时，小结果且无省略不创建快照。通用知识路径首期保持无工具，只提供有界来源摘要并标明不可回读，不为展示引用创建没有消费者的快照。

## 4. 快照与来源语义

“完整”仅指该次调用获准采用的结果。必须分别表达来源是否限行/分页、快照是否完整、当前预览是否省略；不能把预览完整称为来源完整，也不能通过回读绕过来源行数上限。

`result_ref` 是短期访问句柄，原 `source_ref` 仍是证据引用。服务端绑定主体、Run、调用身份、格式版本与授权范围；模型不能指定所有者。同一调用的模型重试复用同一引用，不同调用即使数据相同也不合并为一份证据；不新增 SHA-256 内容校验门。

读取不新增 `EvidenceObservation`、来源或 `unique_evidence_results`，不改变样本量、覆盖率、冲突与充分性，也不重置无进展计数。最终答案继续引用原来源，不能把 `result_ref` 当成新的分析依据。历史会话回放不触发重查或恢复旧引用。

首期只采用一个 Run 内临时文件实现，不预建多后端 Port、对象存储或持久 Repository。优先使用标准库，文件目录按需建立。规范化 JSON 必须有明确格式版本，使用有限且可校验的值；不能用任意对象的 `default=str` 冒充稳定业务序列化。

发布引用前完成大小检查、完整写入及可读性确认；写入中间态不对模型可见。读取通过服务端索引和原有对象/句柄访问，不把模型引用拼接成路径。面对符号链接、Windows reparse point 或发布后的路径替换，应读取原已打开对象或拒绝，不能跟随替换读取目录外文件；具体最小实现由实施设计确定，并在两平台验证。

清理须幂等，释放索引、句柄与文件。首期不承诺进程被强制杀死时立即删除文件；重启后旧引用不可用，残留仅允许在应用自有临时范围安全清理，不增加常驻清理服务。

## 5. 受控回读契约

模型侧暂定名称 `read_tool_result`，契约版本 1.0.0；命名可在实施前按实际消费者调整。

| 项目 | 首期建议 |
| --- | --- |
| 输入 | 有长度上限的 `result_ref`、非负整数 `offset`、有上限的整数 `limit`；拒绝布尔值冒充整数、小数、负数、未知字段和超限输入 |
| 分页单位 | 规范化 JSON 文本的 Unicode 码点位置，不是 UTF-8 字节或 token；`limit` 默认 1024、最多 2048 个码点 |
| 输出 | 引用、原来源/调用身份、`format=json_fragment`、片段文本、实际起止位置、`next_offset`、总字符数及 `has_more`；外层 JSON 有效，片段不承诺可独立解析 |
| 字节约束 | 连同 JSON 转义和元信息检查整个响应；实际页可小于 `limit`，游标按实际返回字符推进 |
| 边界 | 恰好 EOF 返回有效结束页；超过总长度为范围错误；若预算连一个字符及必要元信息都容不下，返回预算错误，不能成功返回无进展页 |
| 禁止输入 | 路径、SQL、脚本、字段查询语言、任意过滤表达式 |

辅助能力按现有单一描述源生成 Schema 和注册视图，挂接本 Run 的现有 Registry/Dispatcher；不另外建一套注册中心，也不改变 Skill 的业务工具依赖声明。

必须在实际读取前检查当前主体、能力、阶段、取消和共享剩余额度。隐藏 Schema 只是展示，不是授权。未知、跨主体、跨 Run 或失效引用统一返回不可用，不泄露其他对象是否存在；授权失败不读取文件或访问来源。

沿用宿主可信身份与既有权限语义，宿主已知的撤销/取消立即拒绝。本项不承诺自动同步尚未接入的公司 ACL。片段作为不可信工具数据接回，不能升级为系统指令。

## 6. 综合阶段与共享预算

### 6.1 开放阶段

| 状态 | 是否可读 |
| --- | --- |
| 诊断业务收集结束，进入允许的综合阶段 | 有引用、授权与剩余额度时可读；Ready 不重新调度业务工具 |
| `required_evidence_complete` 或 `no_progress` | 可以在剩余额度内读取已有结果；不能借此重置停止原因或恢复业务查询 |
| 已达硬调用限额、截止时间、取消、宿主拒绝或保留的最后提交轮 | 不可读 |
| MOD-031 `check_failed` | 不可读、不再调用模型，沿用确定性降级 |
| 通用知识回答 | 首期不可读，保持无工具路径 |

综合响应首期只允许“一次读取”或“一次最终提交”。批量读取、读取混合提交或混合业务调用为协议错误，安全结束且不留下未配对的工具消息；不执行额外业务查询。单次非法引用可在额度内接回有界错误，再继续综合。

Ready 需要实现有限循环。Loop 保留原有模型迭代上限与最后提交轮，不能因为加入辅助工具而新开无限循环。显式 Skill/类型化应用必须通过真实 Run 阶段验收，直接调用存储类不构成接入完成。

### 6.2 调用与模型请求额度

业务实际调用与读取尝试之和不超过原计划生效的总调用上限，读取另限每 Run 4 次，失败读取同样计数。读取不获得额外赠送额度。例如当前计划 5 个业务步骤时，默认上限为 7；完成 5 次业务调用后最多剩 2 次读取，不是另加 4 次。

保留业务计数含义，在实际调用认领边界检查共享剩余额度；不能只在模型请求前估算，也不能重复维护两套业务计数。并发认领必须正确。读取不调用业务结果进展记录，不进入业务每工具限额或必需步骤完成数；已有停止原因优先级保持不变。

建议综合阶段最多 6 次实际模型请求，包含传输重试和修复；Loop 剩余迭代更少时以更严者为准，并为最终提交预留机会。不能仅限制成功响应或逻辑轮数。具体重试路径应在 029a 列清。

建议综合输出总额度不超过该路径原主综合额度加一次修复额度：当前普通主综合为 8192，Ready 的 DeepSeek Thinking 特例为 32768；修复最多一次、2048 token/10 秒，且包含在阶段总额度与总请求次数内。读取、重试不能每次重新领取主综合额度；失败且无法取得 usage 时保守扣除该次预留额度，不能视为零消耗。

建议阶段墙钟截止为首次综合请求起固定的 `api_timeout_seconds`，若已有更早的 Run 截止则取更早者；读取/重试不重置时钟，取消继续传播。上述建议只覆盖本次综合阶段，不声称限制了此前规划、历史上下文或整次 Run 的全部模型消耗。

## 7. 模型视图与存储候选额度

以下为待审核初值，不是已验证性能结果，不改变现有性能阈值。KiB/MiB 按 1024 计；字节不是精确 token。

| 项目 | 候选上限 | 计量范围 |
| --- | ---: | --- |
| 单次业务结果模型视图 | 8 KiB | 摘要、引用、省略与来源元信息整体 |
| 每次模型请求的基础 Tool 派生视图 | 24 KiB | 所有该类视图合计；其中预留 4 KiB 给关键状态/风险及引用元信息，不是额外加 4 KiB |
| 单次读取响应 | 4 KiB | 外层结构、转义后的片段和错误响应均计入 |
| 每 Run 读取 | 最多 4 次、响应合计 16 KiB | 失败尝试同样占次数与实际响应字节；跨轮次不重发额度 |
| 每次请求中基础视图及保留读取响应 | 合计 40 KiB | 24 + 16 的保守合计上限，不是整个模型请求大小 |
| 单份完整快照 | 4 MiB | 完整规范化文本；超限不能伪称已完整保存 |
| 每 Run 快照 | 合计 16 MiB、最多 16 份 | 同时限制容量、文件及句柄数量 |

视图字节按模型最终接收的消息内容字符串的 UTF-8 长度计，包含内容内嵌 JSON 的转义与包装，不等同 HTTP 外层编码长度。实际请求包含相同内容两次就计两次。

检查范围包括普通工具消息、Ready 任务中的结果、保留的历史工具/读取消息、来源摘要，以及从 Tool 数据派生的校验/合同内容。需要在最终请求构建处检查，不能只检查投影函数返回值；聊天模板合并和再次 JSON 嵌入不得绕过额度。

关键失败、冲突、未满足项及充分性状态不能被裁剪为成功或零问题。保留完整内部报告；模型视图采用有界概述和明确省略标志，不能静默截断。替换工具内容时保持调用/响应协议配对。若必要状态本身不能装入预算，停止发送并明确降级。

同一内容跨请求重发仍消耗模型 token，应记录累计发送字节及实际 usage；上述字节上限不等于整次 Run 的 token/费用上限。静态系统提示、用户问题、普通历史、Skill 文本、工具 Schema 与模型输出不计入这项 Tool 内容额度，因此不能保证整条上下文不溢出。

## 8. 失败与 MOD-031 的关系

访问状态仅作为轻量展示/访问摘要，至少区分无需回读、可用和不可用，并携带稳定原因及必要计数；复用现有限制/结果表达，不新增业务 Validator 状态机。

| 情况 | 应有行为 |
| --- | --- |
| 写入/读取失败或存储额度耗尽 | 保留原业务 Tool 成败及证据评估；不给假引用，不回塞无限原文，报告访问限制 |
| 视图裁剪或读取预算耗尽 | 不推断数据不存在，不新增独立证据，不把未见到的行当作检查通过 |
| 原证据不充分或存在冲突 | 保留 MOD-031 的结论与答案约束；回读不改变充分性门槛 |
| `check_failed` | 保留原降级行为，不为“补救”而增加模型/工具调用 |
| 无法构造正确有界的请求 | 不发送超限请求，明确结束或确定性降级 |
| 取消、超时与硬预算拒绝 | 停止读取/模型请求，按既有优先级结束并释放资源 |

对同一份采用结果，开关与读取前后业务评估、样本量和原来源引用应一致；只允许增加展示/访问限制。不得修改 MOD-031 的 each-row、冲突比较、策略版本或正向白名单，不能把访问异常改名为证据检查异常。

最终文本、SSE 完成载荷和持久化结果应一致地表达相关限制，沿用 MOD-031 的答案约束。本项不新增历史结果下载 API 或前端文件浏览器。

## 9. 职责、生命周期与交付边界

Runtime 持有每 Run 的快照、视图额度和读取状态，bootstrap 显式装配。纯投影函数不隐式写文件，业务 Skill 策略与来源 Adapter 不依赖快照 I/O；具体目录和类名可按实际消费者简化，不预设必须增加 Coordinator 或多后端抽象。

实际服务宿主须用覆盖整个 Run 的资源作用域/`finally` 清理，包含提前返回。类型化 `AgentRun` 当前没有关闭协议：启用功能后须提供明确资源作用域，或在缺失生命周期支持时于创建文件前拒绝；不能寄希望于垃圾回收。关闭模式保持旧接口行为。

交付清单按实际依赖更新唯一归属及相关 Profile，不为无消费者的切片扩大依赖。Windows 与 Linux/WSL 均从仓库外的真实交付物运行并核对导入来源。临时数据不是 MOD-021 的持久提交，也不是 MOD-022 的恢复状态。

新增审计只记录必要大小、计数、时延、状态和关联身份，不重复完整载荷或宿主路径。既有完整日志的治理不在本项中顺带重做，也不能据此宣称已解决全项目敏感数据留存问题。

## 11. 验收标准

| 场景 | 通过标准 |
| --- | --- |
| 默认关闭/小结果 | 关闭前后旧行为一致、无新辅助工具；小结果无无谓文件；默认业务工具描述、Schema 和集合逐字节一致 |
| 单行超长/未知工具/嵌套数据 | 真实默认 Dispatcher Loop 与 Ready 的最终请求均有界，不能只测辅助投影函数 |
| 授权与执行采用 | 快照仅含获准采用的数据；执行限行、来源分页和展示裁剪明确区分，读取不能恢复被排除数据 |
| 多结果/派生内容 | 多个单独不超限的结果、Ready 嵌入 JSON、来源片段、派生风险和历史读取响应合计仍受限；重复计入 |
| 分页 | 用手工固定的规范化原文作独立期望；中文、组合字符、引号、换行可重组一致；EOF 与不足容纳一字符的预算不会死循环 |
| 隔离与路径安全 | 跨主体/Run、伪造、过期、撤销、异常参数及路径替换均实际拒绝；无越权来源调用或目录外读取 |
| 共享调用额度 | 业务调用与读取尝试合计不超原上限，包括并发与错误；不改变业务证据或进展计数 |
| 有限综合协议 | 真实 Ready/Loop 夹具先从预览外读取固定目标再提交；混合/批量调用不执行；只直接测试存储类不算通过 |
| 模型额度 | 实际重试/修复纳入次数、输出额度、固定截止时间和最终提交预留；未知失败 usage 不能按零处理 |
| MOD-031 等价 | each-row、缺样本、不可比规格/窗口、冲突、充分性与 `check_failed` 均保留语义、来源及计数 |
| HTTP/SSE/持久化 | 实际入口的结果、事件与保存内容一致；客户端重复请求/历史回放不重查或复活引用，下一 Run 不能读取旧引用 |
| 故障和清理 | 写/读失败、单份/累计超限、异常、取消、超时及提前返回均可观察，正常退出后无遗留句柄/任务；后续 Run 不受污染 |
| 跨平台交付 | Windows/WSL 均从仓库外实际安装制品完成读取与拒绝核心链路，确认无仓库隐式导入 |
| 效果记录 | 固定输入记录完整结果大小、实际模型视图字节、读取次数、模型请求数和时延；不把离线协议通过称为真实模型效果已验证 |

优先扩展已有相关测试，避免为每条规则建立一个重复实现的测试文件。先跑必要定向和真实链路；029e 为阶段结束，按[执行计划](todos/execution-plan.md)和[测试策略](testing-strategy.md)执行完整审计及浏览器回归，不能用定向通过替代。

已有失败与依赖缺项必须在实施起点、同一环境复现并对照；与基线一致不等于全绿，不能放宽阈值或通过自动补依赖掩盖环境差异。真实模型、Live 和公司接口须另有明确授权。本轮文档重审不执行上述实现验收。

## 12. 审核项、替代方案与回退

本版推荐一并审核：默认关闭、Run 临时快照、仅诊断综合阶段读取、JSON 片段分页、与原调用共享总上限、候选字节/文件额度，以及有限模型请求/输出/墙钟额度。它们是项目实施选择，不是通用标准强制项，也不是已经落地的保证。

只做字节投影更简单，但无法满足补读预览外信息的目标；通用文件工具扩大权限面，不采用；持久存储与恢复留给 021/022；首期不引入字段查询语言。若固定样例证明候选额度无法容纳必要状态，应展示样例、替代值与影响后再决定，不能实施时自行提高资源上限或裁掉关键状态。

回退采用新 Run 关闭能力的方式，不在进行中的 Run 中任意切换引用/预算策略；安全撤销则立即停止访问。首期无业务数据库迁移和跨版本持久快照恢复。权限、业务语义、数据来源、冻结阈值或外部行为需要扩大时再向用户确认；内部文件命名和测试组织可合理判断。
