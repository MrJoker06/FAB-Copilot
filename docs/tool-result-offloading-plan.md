目标是让量化小模型接收有限的业务摘要，并在需要时读取同一次调用的完整结果片段，避免按行裁剪无法约束超长字段。卸载针对模型上下文，不承诺降低整个进程的内存峰值，也不承诺所有上下文都不会溢出。

## 2. 当前逻辑与参考结论

| 项目 | 当前 FAB-Agent | Deep Agents 参考 |
| --- | --- | --- |
| 触发 | 指定工具超过行数阈值 | 按工具消息文本大小判断 |
| 模型视图 | 按业务规则排序取前 N 行，标注已展示/总行数 | 文件引用、头尾预览与分页读取说明 |
| 完整结果 | 投影前的运行中证据保持完整 | 写入 Backend，再替换工具消息正文 |
| 回读 | 默认工具无统一的结果回读入口 | 通过 read_file 的 offset/limit 回读 |
| 超长单行 | 可能不触发行数裁剪 | 文本大小触发卸载，预览另限单行长度 |

已做的只读样例：100 条传感器记录在模型视图中取异常最多的 15 条；仅一条、但含 100,000 字符字段时，当前投影不裁剪，生成提示文本为 100,062 字符。这是投影函数的边界，不是对所有真实业务调用大小的断言。

参考实现：

- [FilesystemMiddleware](https://github.com/langchain-ai/deepagents/blob/main/libs/deepagents/deepagents/middleware/filesystem.py)：默认阈值参数为 20,000 token，实际按约 4 字符/token 估算；写入失败可保留原消息。
- [消息卸载与预览](https://github.com/langchain-ai/deepagents/blob/main/libs/deepagents/deepagents/middleware/_message_eviction.py)：保存正文，生成头尾预览和分页提示。
- [StateBackend](https://github.com/langchain-ai/deepagents/blob/main/libs/deepagents/deepagents/backends/state.py)：默认文件保存在会话状态中，不等于真实落盘或减少 Checkpoint 体积。

借鉴“完整快照 + 有界摘要 + 可回读引用”，不直接引入 Deep Agents/LangGraph、不照搬其阈值，也不开放任意文件访问。

## 3. 建议的首期行为

### 3.1 启用方式

建议首期显式启用、默认关闭。策略在 Run 开始时固定；开启后必须能从实际应用入口执行，覆盖 Ready 和 Loop，同时覆盖现有显式装配路径，不能只完成演示脚本。

关闭时保持现有工具清单、结果投影及业务行为；开启时才为该 Run 暴露受控回读能力。默认开启与否是本次审核项，不能仅因完成了开发而自行打开。用户当前的 Thinking 下拉框及档位设置不在本项调整范围。

### 3.2 处理流程

1. 业务工具按既有权限与预算执行，拿到允许当前主体访问的结果；结果过滤先于保存，禁止保存被权限策略排除的字段。
2. 完整结果用于原有证据校验。执行现有业务排序/摘要，并计算完整结果与模型视图的序列化大小。
3. 命中已有业务裁剪、完整结果超过单次阈值，或当前模型视图将超过累计预算时，创建一次完整结果快照。即使业务摘要已经很短，也应能回读被省略部分。
4. 快照成功后，向模型提供有界业务摘要、不可猜测的结果引用、来源、实际大小/行数和省略说明；不返回宿主机路径。
5. 模型可通过受控入口读取片段。回读只读取该快照，不重新查询业务数据库，不重新执行原工具；同一调用在重试综合时复用同一引用。
6. 回读也受主体、能力、调用次数、截止时间和输出预算限制。无须细节时可直接生成最终结论。
7. Run 终结后清理临时快照。旧引用失效必须明确报告，不允许从其他 Run 或新的数据库查询猜测原结果。

原始证据的行数、统计口径、引用及校验结果不因模型视图变短而变化；回读片段不作为第二份独立业务证据重复计数。既有 API 结果不在本项中擅自裁剪。

### 3.3 首期存储建议

建议采用 Run 作用域的临时文件快照，以随机引用映射到内部路径，按需创建目录；小结果且未裁剪时不创建快照。沿用项目忽略规则并使用平台临时目录或明确的运行目录，不引入新数据库、对象存储或向量服务。

文件只由服务端引用映射访问；模型不能传入路径。保存采用完整写入后再发布引用，失败时不返回假引用，也不将无限大原文重新塞入提示。完整结果仍可用于原有证据校验，但须明确报告本轮无法提供回读，并形成受限结论或明确失败。

首期只保证同一次 Run 内可读，不支持重启恢复、跨 Run 共享、持久下载或任意文件操作。引用与来源元信息应能为未来 MOD-021 复用，但不提前实现其原子提交、持久结果及恢复协议。

### 3.4 回读接口建议

暂定模型侧名称为 `read_tool_result`，最终命名可调整。输入仅包含服务端签发的 `result_ref`、非负 `offset` 与有上限的 `limit`，不允许 SQL、路径、脚本或通用查询表达式。

首期建议统一按 Unicode 字符位置分页读取规范化 JSON 文本，以覆盖列表、对象和超长单行，不先建设字段检索语言。返回引用、来源、片段文本、实际起止位置、next_offset、总长度与 has_more；另按实际 UTF-8 字节预算缩短片段。片段标明 json_fragment，不伪称它自身是完整业务结果或可独立解析的完整 JSON；外层工具响应始终是有效结构。

结果引用绑定服务端主体、Run 与调用身份，不能从模型输入决定所有者。未知、跨主体、跨 Run 或过期引用在读取前拒绝，对外不泄露文件是否存在；页边界和中文多字节内容不得引发损坏或无限重复页。

## 4. 初始预算建议（待审核）

以下是首轮候选值，不是已验证性能结论，也不修改现有性能门。KiB/MiB 按 1024 计，不把字符或字节伪称精确 token；具体参数落点和命名在实施设计中确认。

| 项目 | 建议初值 | 说明 |
| --- | ---: | --- |
| 单次模型可见工具消息 | 8 KiB | 包含摘要、引用和省略元信息；已有业务裁剪也触发快照 |
| Run 中基础工具结果的累计视图 | 24 KiB | 包括进入当前模型消息的工具内容及 Ready 证据视图，不只检查单个工具 |
| 每次回读响应 | 4 KiB | 包含片段与元信息，limit 另有字符上限 |
| 每 Run 回读 | 最多 4 次、合计 16 KiB | 与原执行调用数和截止时间同时约束，不提供额外无限预算 |
| 单份完整快照 | 4 MiB | 超出时明确结果超限，不伪装为完整保存 |
| 每 Run 完整快照 | 合计 16 MiB | 写入前检查；不以结果引用绕过存储上限 |

原业务视图与回读内容须分开计量，明确总消耗；不能在每次模型请求重新发放预算。历史、系统提示、工具 Schema 和模型输出不在上述工具内容额度内，因此不能据此宣称整条请求一定适配模型上下文。审核后可按固定样例调整候选值，并记录依据。

## 5. Ready、Loop 与权限预算

| 路径 | 拟调整 | 必须保持 |
| --- | --- | --- |
| Loop | 在原工具结果进入模型消息前应用快照/摘要；加入本 Run 允许的回读能力 | 原业务工具的权限、范围、重复调用约束与证据语义；回读计入预算 |
| Ready | 保持确定性业务计划，综合阶段允许有限的“回读或最终提交”循环 | 模型不能重新调度业务工具；超限/取消时明确结束，不能把缺失片段当作不存在 |
| 显式装配 | 注入同一 Run 作用域的结果管理与读取能力 | 不修改全局注册表或其他 Run 的能力，主体和引用由服务端绑定 |
| 运行结束 | 在成功、异常、超时、取消和综合失败时关闭资源、清理快照 | 无残留任务/句柄；权限拒绝不访问来源；后续 Run 不受污染 |

当前 Ready 综合主要围绕最终提交，仅把 read_tool_result 加进清单不足以完成此项。需要明确模型轮数、读取响应接回、最终提交和耗尽后的策略；具体总轮数与模型调用预算随执行器设计一起审核，不以读次数上限替代完整控制。

保存成功不授予读取权限，引用也不授予跨主体能力。分页不能绕过结果过滤或读取未授权字段；若运行中权限撤销，沿用当前有效权限语义并明确拒绝。新增卸载/回读日志只记录必要元信息，不重复输出完整结果、凭据或宿主路径；既有审计保留原策略，但不能替代结果回读存储。

## 8. 验收标准

| 场景 | 通过标准 |
| --- | --- |
| 关闭功能 / 小结果 | 默认业务行为与已有结果一致；无不必要的快照写入；未启用时不新增回读工具 |
| 单行超长、超长字段、未知工具、嵌套对象 | 不依赖行数或已知工具名触发；实际发往模型的内容在预算内，并明确是否完整 |
| 原业务裁剪 | 保留异常优先等领域规则；摘要外结果可通过引用读取；证据指标仍基于完整授权结果 |
| 多工具累计 | 构造各自较小但合计超限的固定结果；累计预算确实生效，元信息本身也计入，不无限追加引用消息 |
| 分页正确性 | 按返回的 next_offset 重组后与手工固定原文一致；中文、引号、换行与超长单行不丢失、重复或损坏；响应结构有效且标注片段 |
| 数据与权限 | 同 Run 合法主体可读；跨主体/Run、伪造/过期引用、负 offset、过大 limit、权限撤销均明确拒绝；不接受路径/SQL |
| 业务来源调用 | 首次只按原计划查询；多次回读不会增加原业务源调用；不重复计入业务证据 |
| Ready / Loop | 两条路径都能通过回读得到预览外的固定答案，只有 submit 成功不算回读验证；Ready 不执行额外业务工具 |
| 失败和预算 | 写失败、读失败、单份/累计存储超限、回读耗尽、模型异常与取消均可观察；不得返回坏引用或将无限正文回塞提示 |
| 生命周期 | 成功/异常/取消/超时后目录与句柄按策略清理；旧引用失效；后续 Run 与干净运行一致；测试不写开发配置或真实数据 |
| 可搬迁 | 两端在新环境从交付物完成以上核心演示，无仓库隐式导入；只为新增能力更新必要清单 |
| 效果证据 | 对固定输入记录完整结果大小、模型视图实际字节数、回读次数、额外模型调用与延迟；不预先承诺节省比例或声称量化模型效果已验证 |

先运行必要定向与真实链路，再按执行计划判断完整质量门。性能阈值不擅自修改；真实量化模型测试需另有明确授权，Fake 通过仅证明协议与工程行为。此次写计划不执行上述测试。
