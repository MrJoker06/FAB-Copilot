# MOD-029：Tool 大结果卸载与 Session 级受控回读方案

版本：v3.0 重审稿。修订日期：2026-11-15。源码核对起点：`c5312d1`，分支 `experiment/parallel-platform`。本版替代 v2.0 的 Run 内临时文件方案；旧调用链分析只作检查线索，实施前须重新核对。

**状态（2026-11-16）：029a～c 已实现，029d 已接入实际聊天、后台和 Session 删除；029e 阶段验收进行中，尚未整体完成。** 历史分批事实见 [029a](reports/mod-029a-result-access-contract.md)、[029b](reports/mod-029b-result-store.md)、[029c](reports/mod-029c-result-read-tool.md)，当前接入、修正和验收限制见 [实施报告](reports/mod-029-tool-result-access.md)。

本项获准实施后排在 MOD-025 前；随后保持 025 → 026 → 027 → 028，恢复链 020 → 021 → 022 → 023 按需求启用。模块化未完成仍为 9 项，产品统计仍为 228/183/45。

## 1. 目标与已确认方向

减少模型接收的工具结果内容，保留本次获准采用的结果快照，让同一 Session 的后续运行在授权和预算内按需回读，支持连续追问与复核同一批结果。

用户已确认：

1. 默认开启卸载，后台保留显式关闭/开启按钮；两种模式都限制模型视图大小。
2. 关闭后的直接截断提醒与开启后的成功卸载提醒分开处理；异常另行提示。
3. 使用独立结果库，结果寿命绑定 Session；永久删除 Session 时清理关联结果。
4. 引用回读，列表优先按完整记录、文本按段落分页；超长单元再降级为明确标记的片段。
5. 限制单结果、单 Session 和总容量；容量不足明确提示，不静默淘汰尚存 Session 的结果。跨轮回读标明原查询时间、范围，使用当前运行预算。

本项不允许模型生成或执行任意 SQL，不开放路径、脚本或自由查询语言，不新增 SHA-256 内容校验门。结果库属于应用自有状态，不是生产数据源、RAG 文档或长期记忆。

新增持久结果不等于 MOD-021 的业务结果原子提交、MOD-022 的中断恢复或 Agent 续跑；不提前完成恢复链。首期也不保证全进程内存峰值下降、整条上下文适配任意模型或真实小模型准确率提高。不自动接入公司数据库、LDAP 或 Live。

## 3. 默认流程、后台开关与提醒

1. 宿主验证 Session 与调用者权限，在 Run 开始时固定开关、Session 和预算；模型不能指定所有者。
2. 原工具完成权限、来源调用、过滤和执行限行，形成采用结果并进入原业务证据链一次。
3. 构造有界预览，保留异常优先等业务排序；无省略不保存无谓快照或发送卸载提醒。
4. 开启、发生省略且接入路径支持回读时，在结果库事务内检查配额并保存完整快照及分页结构；成功提交且可读才发布随机引用。关闭时直接截断为有效预览，无新快照/引用；其他保存或访问失败提示实际原因。
5. 在允许的阶段使用引用回读，不重查业务来源；同 Session 后续 Run 可再次授权读取。实际模型请求发送前检查所有派生视图及保留回读响应。
6. Run 结束释放运行资源，已提交结果保留；Session 永久删除时清理。无法构造正确有界请求时明确结束/降级，不回塞无限原文。

### 3.1 后台设置

复用现有管理设置及服务端权限，提供“大结果卸载”开关和当前保存状态。未配置默认开启，显式关闭值跨重启保留；配置读取失败明确报错，不当成用户关闭。验证布尔值及管理权限，普通聊天请求和模型不能修改全局设置。

保存时提示“对新运行生效”；进行中 Run 使用固定策略，安全撤销、取消与 Session 删除立即限制访问。关闭后新 Run 不再保存新结果，也不开放辅助回读；已有结果保留，不把关闭变成删除。重新开启后可按当前权限读取已保存结果，不能恢复关闭期间未保存的内容。开关不关闭视图大小、业务权限或证据检查。

无有效 Session 的独立/Typed 入口可生成有界预览，但不隐式创建会话或无归属记录；发生省略须提示“当前入口无 Session，未保存、不可回读”。

### 3.2 分支提醒

提醒由服务端根据实际状态生成，分别表达展示省略、保存成功和当前可读性；不能仅凭开关生成。复用现有结果、SSE、会话元信息，不新建通知平台，字段/错误码在实施时对齐现有消费者。

| 情况 | 用户与模型须得到的信息 |
| --- | --- |
| 关闭且本次结果省略 | **截断提醒**：“卸载已关闭，本次结果仅保留部分内容，省略部分未保存、不可回读。”无新引用 |
| 开启且完整保存、当前可读 | **卸载提醒**：“当前展示预览，本次调用获准采用的结果已保存，可在当前会话中按需读取。”附真实引用、原查询时间/范围；不等于已读完或来源全部数据 |
| 开启但写入失败、超容量或入口不支持 | **访问限制提醒**：具体说明省略及未保存/不可回读原因，无假引用，不误报用户关闭 |
| 已保存但当前开关/授权/预算拒绝 | 保留“已保存”事实，说明当前访问限制，不能误称已删除或保存失败 |
| 无展示省略 | 不发截断/卸载提醒；来源自身限行或分页仍单独提示 |

在用户可见工具状态区域显示，并与流式事件、完成载荷和会话保存一致。同一调用重放不重复生成提醒。历史页面只显示已有记录，不自动回读或重新查询；引用不再一律随 Run 结束失效，当前可用性由服务端检查。模型最终回答保留影响结论的限制，不能声称已分析尚未读取的全部快照。不新增完整下载 API。

## 4. 独立结果库与跨轮语义

### 4.1 物理存储与职责

首期一个独立 SQLite 结果库，多 Session 共用并按归属隔离，不为每个 Session 建库。`tool_results.db` 为示例名，路径由可信宿主配置，模型和聊天请求不能传入。与业务、模拟及知识来源数据库分开，不自动迁移已有文件。

Runtime 负责保存时机、引用携入和视图/读取预算；persistence 负责结果库 Schema、连接、事务与固定参数化操作；会话用例负责永久删除编排；bootstrap 显式绑定。纯投影、业务策略、Validator 和业务 Adapter 不依赖结果库 I/O。不预建多后端平台或无消费者抽象。

### 4.2 数据内容与发布

以下规定事实而不冻结表名，029a 决定最小 Schema：

| 内容 | 必须表达 |
| --- | --- |
| 归属/身份 | 随机 result_ref、租户/所有者、Session、原 Run、原工具调用、原 source_ref、工具名 |
| 时间/范围 | 查询完成时间、对象和数据时间范围、来源限行/分页；未知值明确未知 |
| 内容/格式 | 格式版本、完整获准结果、原始顺序、分页单元及必要外层结构/单位 |
| 发布/容量 | 实际存储字节、单元/结果计数、提交/可用状态；未提交不发布 |
| 生命周期 | Session 删除撤销状态、必要的幂等身份与持久清理标记 |

“完整”只指本次来源返回且获准采用的结果，不是来源全部数据。规范化使用可验证 JSON 值，不以 `default=str` 冒充稳定格式；原正文和分页结构若重复存储，全部计入容量，不能只计算预览。

同一 Session/同一调用的技术重试复用已提交引用；不同调用即使内容相同仍保留各自来源和时间，不做跨用户或跨 Session 内容去重。配额认领、内容写入与发布在结果库事务内完成，失败整体回滚，并发不能超卖容量。

### 4.3 引用与授权

result_ref 是定位句柄，不是授权凭证或新证据。每次读取检查当前主体、Session 存在且未删除中、能力、开关、阶段、取消及当前预算。未知/跨主体/跨 Session/已删除引用统一不可用，不泄露其他对象是否存在；同 Session 跨 Run 允许，不再按原 Run 一律拒绝。宿主已知的权限撤销立即拒绝，不承诺自动同步未接入的公司 ACL。

重启后已提交结果在格式兼容、Session 有效且授权成立时继续可读；不兼容明确报错，不静默误读或删除。Session 转移、共享、导出不隐式授权。当前 Run 只携入宿主允许的引用和有界元信息，不自动加载 Session 全部快照，也不开放任意目录浏览或搜索。

跨轮回读返回原查询时间和范围，不刷新业务来源、不将旧结果冒充最新数据。用户要求最新数据时走正常业务查询。历史页面重放本身不触发读取或模型调用。

回读同一调用的不同页不新增 EvidenceObservation、来源或 unique_evidence_results，不改变样本、覆盖率、冲突、充分性或进展计数。跨轮查看原结果沿用原来源与时间说明，不自动满足新运行的必需证据步骤；将历史结果正式纳入新诊断的采信规则另行设计，本项不悄悄实现。快照解释不能默认升级为新的生产诊断结论。

## 5. 专用回读与分页

辅助 Tool 暂名 `read_tool_result`，契约初始版本 1.0.0，按现有单一描述源生成 Schema 并挂接每 Run Registry/Dispatcher。模型只传引用和分页参数，服务端执行固定参数化操作；不允许模型生成或执行 SQL。

| 项目 | 首期设计 |
| --- | --- |
| 输入 | 有长度上限的 result_ref、可选不透明 cursor、正整数 limit；候选默认 20、最多 50 个逻辑单元，最终受字节上限约束 |
| 正常分页 | 列表按完整记录，文本按保留内容的段落；嵌套对象保留根结构说明和确定的单元身份，不随意拍平 |
| 正常输出 | 有效 JSON，含原来源/时间/范围、格式版本、单元类型、有序单元、实际范围/总单元数、next_cursor、has_more 和省略信息 |
| 超长单元 | 单记录/段落无法装入时，明确标记片段格式、单元身份、片段起止和续读位置；片段可非独立 JSON，但外层必须有效，不伪装完整记录 |
| 游标 | 不传从首单元开始；绑定不可变快照、版本、单元和片段位置，拒绝跨引用挪用/伪造；不代表授权，不解释成路径/SQL |
| 前进/结束 | 按实际返回内容推进，末页明确结束；预算连一个字符和必要元信息也容不下则报错，不成功返回无进展页 |
| 拒绝输入 | 布尔冒充整数、非整数、负数/零 limit、未知字段、超限值、路径/SQL/脚本/自由过滤表达式 |

超长单元候选每片最多 2048 Unicode 码点，整体仍受 4 KiB 响应上限约束，不能只数记录条数。029a 固定复杂类型的无损存储、分页与重组规则、游标和独立预期；不支持的类型明确报告。回读不隐式排序、过滤或统计，不新增通用 read_file、全文搜索或数据库浏览器。

## 6. 阶段许可、调用与模型预算

| 路径/状态 | 许可 |
| --- | --- |
| 业务收集结束后的允许综合阶段 | 可读本轮及同 Session 经宿主允许携入的旧引用；Ready 不重新调度业务工具 |
| 用户明确复核同 Session 旧结果 | 宿主经已有上下文绑定目标，提供有限快照查看/解释入口，不因只有回读而强迫重跑业务步骤 |
| required_evidence_complete / no_progress | 剩余额度内读取，不重置停止原因或恢复业务查询 |
| 硬限额、截止、取消、宿主拒绝、Session 删除中、最后提交轮 | 不可读 |
| MOD-031 check_failed | 不增加模型或读取调用，沿用确定性降级 |
| 通用知识回答、仅打开历史页面 | 不开放回读工具或自动读取，不将普通浏览变成 Agent 执行 |

029a 明确旧结果追问如何通过真实宿主进入有限综合，不只测试存储类。若上下文不能确定目标则澄清，不猜引用或搜索整个 Session；无需借此实施全套路由改造。此入口由宿主明确分配有限调用预算，不能因没有业务步骤就无限读或直接继承原 Run 剩余额度。

业务调用与读取尝试共享当前 Run 总上限；读取另限最多 4 次，失败也计数。例：5 个业务步骤、总上限 7，完成业务后最多剩 2 次读取，不另赠 4 次。在实际调用认领处检查并发，读取不进入业务每工具限额、必需步骤数或进展统计。新 Run 使用自己的预算，但当前 Run 内不得通过重试/分页重新发放。

综合响应首期只允许一次读取或一次最终提交；批量/混合读取提交/业务调用为协议错误，正确结束和配对消息，不执行额外调用。Ready 有限循环，Loop 保留迭代上限、最后提交机会和停止原因。

保留 v2 待审候选：综合最多 6 次实际模型请求，含传输重试与修复；总输出不超过原主综合加一次修复。旧基线普通主综合 8192、Ready Thinking 特例 32768，修复最多一次 2048 token/10 秒，实施前核对。失败 usage 不明时保守扣除预留，不算零消耗。阶段截止从首次综合请求起固定为 api_timeout_seconds 或更早 Run 截止，读/重试不重置。

## 7. 模型视图和存储候选额度

以下为待审核初值，不是验证结果，不改变冻结性能阈值。KiB/MiB 按 1024，字节不是 token。

| 项目 | 候选上限 | 范围 |
| --- | ---: | --- |
| 单结果模型视图 | 8 KiB | 摘要、引用、时间/范围及省略元信息整体 |
| 每请求基础 Tool 派生视图 | 24 KiB | 内含 4 KiB 关键状态/风险/引用预留，不另加 |
| 单次读取响应 | 4 KiB | 外层 JSON、转义、元信息、错误响应整体 |
| 每 Run 读取 | 4 次、响应合计 16 KiB | 含失败，本 Run 内不重发 |
| 每请求基础视图加保留回读响应 | 40 KiB | 24 + 16，不是整条模型上下文上限 |
| 单快照 | 4 MiB | 实际持久内容及分页结构，不只预览 |
| 单 Run 新写入 | 16 MiB / 16 份 | 已提交计数不因取消清零，回读不重复占存储 |
| 单 Session 保留 | 64 MiB / 128 份 | 所有 Run 合计，归档也占用 |
| 结果库全部有效内容 | 1 GiB / 4096 份 | 所有 Session 合计，待清理内容仍占用 |

存储配额在事务内认领，不能无保护地先查用量后插入。正文/索引副本计入内容配额；SQLite 索引、日志和空闲页还有额外占用，内容配额不是物理磁盘上限。另检查可用空间并正确处理磁盘满、锁冲突及提交失败。超限拒绝新保存并明确提示，不静默淘汰活跃/归档 Session，不自动改开关或阈值，不隐含年龄过期策略。

模型视图按最终消息内容字符串 UTF-8 长度计，含 JSON 包装和转义，重复出现重复计入。覆盖两种 Loop、Ready 嵌入结果、来源摘要、派生风险/校验与保留历史回读消息，最终请求组装处检查，不能被聊天模板合并绕过。

必要失败、冲突、未满足项及充分性状态不能裁成成功；保留完整内部报告，必要状态无法装入则停止/降级。静态提示、用户问题、普通历史、Skill、工具 Schema 与模型输出另计，因此不保证整条上下文永不溢出。记录累计发送字节与实际 usage，不把每请求额度当成 Session 总费用上限。

## 8. Session 生命周期与删除一致性

| 事件 | 处理 |
| --- | --- |
| Run 成功/失败/取消/超时/提前返回 | 关闭连接/游标并回滚未提交写入，保留已提交快照 |
| Session 归档/恢复 | 保留结果；归档本身不新增授权，恢复后仍检查当前权限和开关 |
| 单个/批量永久删除 | 进入禁止新增读写的删除流程，清理全部关联快照和分页数据 |
| 进程重启 | 已提交结果保留，恢复未完成清理；不因无进程内句柄就宣告丢失 |
| 清理失败 | 保留持久待清理状态并重试，不伪报清理成功，孤立结果不可读 |

### 8.1 最小可靠删除协议

SQLite 无跨 Schema 外键；现有内存挂载入口和部分 WAL 配置不能承诺跨文件崩溃原子提交。采用会话用例编排与持久删除意图，不建设通用分布式事务平台：

1. 在会话应用状态中持久记录永久删除意图及归属，新执行/读取/写入据此拒绝。复用已有机制；若没有，新增仅服务本用例的最小记录，不靠内存锁/进程队列。
2. 协调在途 Run 取消/结束，在结果库事务内设置 Session 写入撤销标记并清理。发布与撤销/清理以结果库事务序列化：先提交的写入被清理，撤销后的写入拒绝，不能让迟到回调重新造出结果。
3. 清理确认后，在会话事务中永久删除 Session 并完成删除意图，再返回完整成功。跨库不声称全有或全无；失败时可能暂留“删除中”，须报告错误/待清理。
4. 启动/维护入口幂等重放待删除记录，确认无剩余内容后完成；失败继续保留状态。批量逐项报告完成与未完成，不伪报整批成功。

029a 给出写入/删除并发、各崩溃窗口、锁顺序、重复请求及恢复的具体协议，不能用“最终会清理”代替实际保证。删除/撤销在读取实际边界生效，不能撤回已发送字节；明确读写线性化边界。宿主数据库路径拒绝不受信路径和符号链接/reparse point 绕过，result_ref 永不拼接路径。

删除记录释放可复用空间，不保证文件即时缩小或磁盘安全擦除。物理回收采用明确 SQLite 维护策略并提供证据，不每次删除就无条件全库 VACUUM；不承诺清除外部备份、原业务来源和既有日志。

## 9. 失败语义与 MOD-031 边界

展示省略、保存、可读及拒绝原因分开表达，复用限制字段，不新增业务 Validator 状态机。

| 情况 | 行为 |
| --- | --- |
| 结果库不可用/损坏、配额或写入/提交失败 | 保留原业务 Tool 成败及采用结果；无假引用，不发送无界原文，报告保存限制 |
| 引用拒绝、Session 删除中、无权访问 | 不读正文、不查来源；对无权调用方统一不可用，内部只留脱敏原因 |
| 分页或读取预算不足 | 说明只见到部分内容，不推断其他数据不存在或已验证通过 |
| 业务证据不足/冲突、check_failed | 原评估/降级不变，回读不修复等级或追加独立观察 |
| 取消/超时/硬限额 | 停止当前操作并释放资源，Session 未永久删除时保留已提交结果 |
| 无法构造正确有界请求 | 不发送超限请求，明确结束或确定性降级 |

最终文本、SSE 与保存结果一致表达限制。each-row、规格/窗口可比性、冲突、业务策略版本及答案正向白名单不在本项修改；访问异常不能改名为证据检查异常。新增审计只记大小、计数、状态、时延与必要身份，不重复正文或暴露宿主连接信息。

| 场景 | 通过标准 |
