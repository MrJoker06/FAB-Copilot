# Issue #2 第 6 项 · PE / EE 值班助手的回答依据

实施方案 v0.4，2026-11-19。产品范围采用已确认的 A 方案，负责查数、交接、辅助排查和转述现场已确认的决定。当前实现与验收边界见[实施报告](reports/issue-2-duty-answer-evidence.md)。[需求记录](https://github.com/MrJoker06/FAB-Copilot/issues/2)

## 1. 新任务取消整轮五档

保留 Validator，复用现有逐条结论和工具调用引用。新任务直接核对工程师所问的每件事，移除整轮结论强度的计算、提示和展示。旧会话按原记录回读。核对结果由服务端用于组织答案，量化模型无需评分。

| 工程师问什么 | 助手需要核对什么 | 缺少依据时怎样回答 |
| --- | --- | --- |
| 当班的数值或事件 | 来源、对象、时段、字段值和单位；报告零条还须确认查询成功且完整 | 报告缺哪个来源或时段。已经查实的其他事实可以先答。 |
| 是否超标或发生变化 | 同一口径的实测数据、适用规格版本或可比时段 | 给出已查读数，说明缺少哪个比较依据。 |
| 为什么异常、下一步查什么 | 把现场观测、SOP 推荐步骤、相似历史 case 各自归到原来源；提出假设时给出核查办法 | 可以建议查什么；当前根因尚待确认。 |
| 某批是否已放行、根因是否已确认 | 对应设备或批次的现场确认记录、状态与时间 | 说明当前查到的状态和待人工确认项。正式判定单由现场负责。 |

工程师应能看到生产事实的来源、适用范围和影响使用的限制。同一来源和范围可以合并说明。遇到冲突时分别注明来源、口径与查询时间；跨轮使用旧结果时注明原查询时间。

## 2. 一轮回答怎样完成

1. 按现有路由确定对象、时段和请求。根据本问需要的依据调用已授权工具。关键范围不清时先澄清。
2. 从成功的实际调用核对数值与引用。若缺项直接影响本问，且有可用来源和剩余预算，就针对该缺项补查。查不到时说明具体缺口，返回能独立核实的部分。权限拒绝、必需检查故障仍按原执行边界处理。
3. 在展示生产事实前完成核对。Ready、Loop、流式正文、降级回答和会话回读遵循相同的结论边界。进度展示已经查到了什么、还缺什么。

例如，假设夜班报表返回 CMP-02 的 Cpk 为 0.92。工程师只问读数时，回答“CMP-02 夜班 Cpk 为 0.92（来源：该机台夜班能力报表）”。若追问是否由温漂导致，才需要核查同期温度。温度来源超时时，保留读数并说明“同期温度记录读取超时，本次无法判断温漂与该指标的关系”。

## 3. 实施范围与验收

源码参考基线为 `fe505eb`。从 [Validator](../app/evidence/validator.py) 和[答案综合器](../app/evidence/answer_synthesizer.py)移除新任务对 `allowed_conclusion_strength` 的依赖，同步更新 Ready、[Loop](../app/agent_runtime/execution/loop_round_validation.py)、旧式文本入口、提示、事件与回读。为新输出标记契约版本，旧记录中的档位可照原样读取。保留策略检查状态；适用策略下的 `evidence_sufficient` 直接根据必需项覆盖和严重问题计算，供取证流程使用。权限、预算和来源访问沿用现有机制。

| 验收范围 | 通过条件 |
| --- | --- |
| 首批 · Cpk 与班次报警 | 同一读数配上正常或超时的温度来源，读数、对象、时段和引用都一致，只有温度判断随证据变化。只问 Cpk 时不调用温度来源。完整查询零条、分页未完、拒绝和超时给出各自真实的结果。 |
| 扩展 · 值班工作 | 用独立案例覆盖跨班交接、报表切换机台、设备报警与恢复、制程异常、SOP 版本、历史 case 适用性和现场放行记录。逐例写明必须保留的事实、应披露的限制和禁止断言，加入来源冲突与跨轮追问。 |
| 放行 · 用户实际收到的答案 | 在冻结样例及留出问法中核对事实与引用。必答事实完整；错数、错对象、越权信息、虚报零条、无依据根因和放行结论均不得出现。核对流式正文与会话回读，以及旧会话可读性。在 Windows 和 WSL 按[测试策略](testing-strategy.md)运行适用的离线质量门，分别记录结果与未验证范围。 |
