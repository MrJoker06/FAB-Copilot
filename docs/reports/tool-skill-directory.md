# 值班助手的工具与技能目录

平台管理员在「工具与技能」中切换 Tool 和 Skill 页签。工程师从「所有功能 → 工具与技能」查看当前身份可见的目录。两者分别配置，业务分组用于检索，例如「设备健康」或「值班交接」。

## 注册与使用

1. 先由部署者提供工具实现或 Skill 包。打开管理后台的注册对话框，选择已经部署的能力，查看接口、版本或技能依赖。
2. 选择通用，或指定一个归属部门并填写额外开放部门。勾选「启用」后保存。只有平台管理员可以注册、编辑、停用或重新启用。目录授权保存到 Agent 运行状态目录的 `capability_directory.db`，备份和恢复实例时一并保留。
3. 常用的 21 项业务 Tool 与 Lot 共性分析专用的 3 项 Tool 默认通用、启用。Lot 工具仅在 Lot 分析路由提供给模型。扩展 Tool 和 Skill 由管理员显式注册。对已有 Tool 的限制同时作用于新运行提供给模型的工具清单、Ready 和 Loop 的实际 Dispatcher 调用。进行中的调用已返回的数据不会被撤回，后续调用重新检查当前授权。
4. 当前本地演示身份没有受信部门，普通页面仅可使用通用范围。企业接入后，成员关系应由服务端身份提供方写入 `Principal.modules`。客户端提交的部门头不能获得访问权。

## 能力包

- **Tool** 复用 `ToolDefinition` 声明名称、描述、版本和输入输出，运行时提供对应的 `ToolBinding`。外部部署包可在 Python 包元数据中声明 `fab_agent.tools` 入口点。其工厂返回 `InstalledTool(definition, routes, bind)` 集合，`routes` 是适用的路由意图，`bind(settings, principal)` 返回使用同一份定义的绑定。安装受信包后重启进程，再在后台注册。既有路由、角色、租户、数据源与计划预算继续生效。
- **Skill** 的基本单位是包含 `SKILL.md` 的目录，沿用项目已有的标准解析器。默认扫描 `app/skills/*/SKILL.md`，部署时可通过 `FAB_SKILLS_ROOT` 指定目录。只有说明文件的 Skill 可以作为操作指引注册。带执行清单的包须为 `published` 并通过校验才能启用。
- **依赖检查** 按当前用户核对 Skill 声明的 Tool 名称、版本与可用范围。工程师能看到自己获准查看的 Skill；缺少依赖时页面提示未就绪，并隐藏使用说明和依赖明细。管理员可以检查具体缺项。注册 Skill 提供目录发现和说明读取，聊天自动选择及启动工作流属于单独的执行能力。
- **光刻示例** 可分别注册 `get_capability_trend` 和 `litho-cpk-diagnostic`。前者使用已有的只读制程能力周趋势实现。后者声明五项工具依赖；给同一部门开通 Skill 和相关工具后，该部门可查阅完整说明。单独扩大 Skill 的可见范围不会给其他部门授予 Tool 执行权。

## 验收入口

`tests/test_capability_directory.py` 验证管理员注册、身份伪造拒绝、跨部门可见性、依赖限制、无效包隔离，以及在临时制造库读取实际周趋势和对运行中工具撤权。Chromium 的 `tests/e2e/duty-management.spec.js` 验证后台注册通用 Skill、工程师查看和改为部门专有后再次查询的结果。公司身份与报表平台登录独立接入。

- 最终版 Windows 定向测试 59 项通过，含交付包测试。WSL 定向测试 50 项通过。用临时制造库验证了已授权部门查询到光刻设备行，以及停用后已装配运行的下一次调用被拒绝。用户目录单独验证了平台身份要求，并可在个人上传配置了独立令牌时工作。

- Windows 完整门首轮发现交付测试仍预期 339 个成员。核对新增 3 个应用包文件并更新成 342 后，重跑的非系统阶段共 1522 项，含 4 项跳过。随后因已有耗时清单缺少 `tests.system.test_lot_commonality_api`，完整门在系统测试阶段启动前停止。另以独立进程运行 6 个系统模块，91 项通过。最后新增的目录身份与无效包用例计入定向测试，完整门没有再重跑。

## PE / EE 分支集成

PE / EE 分支的 Lot 分析继续支持从页面带入已有分析引用，也支持在会话内创建分析和下钻。三个 Lot Tool 共用能力目录和 Dispatcher 策略，各自可按部门启停。聊天携带旧分析引用时，服务端先核对该用户对创建分析工具的权限，再检查引用归属和会话状态。同步和流式入口都会在写入消息、读取摘要及调用模型前拒绝失去授权的附件，返回 `CAPABILITY_DENIED`。页面独立查询沿用 Lot 分析接口的租户、引用归属和会话权限。

合并基线为 PE / EE 的 `8a32593` 和权限分支的 `258ec42`。Windows 定向 58 项和 Lot 会话系统测试 4 项通过。后者覆盖允许时产生会话分析、缩小部门范围后模型清单不再包含该工具，以及同步和流式请求带旧引用时的拒绝。在 WSL 原生文件系统的隔离副本使用合成库执行完整离线质量门，Python 1628 项（3 项跳过），7 个系统模块 95 项，合计 44.8 秒，分支覆盖率 89%，Node 85/85，Chromium 46/46。Lot API 与 Lot 会话系统模块分别耗时 3.6 秒、7.9 秒。公司 Qwen、LDAP 与 MES 接入仍待现场验证。
