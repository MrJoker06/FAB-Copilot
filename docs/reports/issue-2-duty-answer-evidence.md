## 实施

- 新任务的验证、回答契约与综合报告使用 Schema 1.3。移除任务级五档字段和计算。Ready 与 Loop 进度展示必需项覆盖，答复按来源披露实际缺项。取证仍使用必需项覆盖、检查状态和严重问题，旧会话按存档读取。
- 默认装配为单机台简单 Cpk 和报警问题使用单工具计划。Cpk 从已授权的制程报表筛出目标机台，直接呈现来源、实际日期、指标值和样本数。报警从设备事件时间线计数，区分正常零条、读取失败、权限拒绝和达到 100 条上限。服务端渲染的结果用于流式正文和历史。
- 综合诊断复用逐声明引用。对 Cpk 明示数值核对调用中实际返回的数字、机台、单位和日期。某个取证调用失败时，单独说明该来源的缺口。引用或措辞越界的结论从受约束的展示正文中省略。
- 现有 Cpk 与报警来源的查询窗口是日期。班次请求先说明这一限制，并请工程师确认是否查全天。将厂内班次时钟和签核状态接进真实来源后，可用同一模式补充班次值和状态转述。当前值班助手可整理交接与排查依据，正式判定由现场负责。
