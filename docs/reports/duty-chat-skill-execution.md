# 值班聊天的 Skill 选择与执行

基线为 `feat/pe-ee-duty-workspace` 的 `48255b7`。关联 [Issue #2 第 3 项](https://github.com/MrJoker06/FAB-Copilot/issues/2) 和[开发清单](../duty-chat-skill-execution-plan.md)。

## 使用和运行行为

1. 在值班聊天点击「选择技能」，选择「光刻 Cpk 排查」的已发布包并应用。选择只用于下一次发送，可以在发送前恢复「按意图选择」。同步和流式聊天使用可选 `skill_id`，前端重试保留原选择。
2. 未手动指定时，现有意图解析和仲裁将**明确指向光刻制程的 Cpk 诊断**交给已注册且当前身份可执行的 Skill。模型辅助的上下文解析仍由现有流程处理。本试点只装配一个工作流，选择过程无需额外的模型请求。普通概念问答和无匹配请求沿用现有路径。
3. 光刻工作流沿用已有整站点口径，日期必须明确。请求指定单台设备或其他制程时，先请用户确认该 Skill 的范围。班次词和默认推定日期进入追问。后续仅对上一轮确实缺少的日期或光刻范围确认延续该 Skill。
4. 聊天成功或澄清时，回复与会话元数据记录选择方式、Skill 版本和工作流版本。真正的工具执行、数据来源、限制与引用由原有 Planner、Dispatcher、证据检查和结果存储提供。

## 权限与兼容

管理员仍在「工具与技能」中注册光刻 Cpk 包及制程能力周趋势工具。服务端按租户、角色、部门、登记状态和依赖版本检查，只有本次已装配的依赖进入 Skill 工具集合。同步与流式入口共用检查；执行、综合及缓存结果重试使用当前授权。普通聊天组装模型历史时过滤已撤权的 Skill 回答。历史页面和通用结果回读的企业授权沿用 [Issue #3](https://github.com/MrJoker06/FAB-Copilot/issues/3)。

附带 Lot 快照或回读已保存结果使用各自的请求入口。现有请求无需提供 `skill_id`，旧会话兼容。所有本地验收使用合成数据、测试身份、本地模型夹具或确定性降级。

## 验收

- 原生 Windows 会话系统测试 18 项与 Chromium 管理及无障碍用例 7 项通过。专项验证真实 Dispatcher、显式选择优先、时间追问和补齐、无匹配回退、依赖拒绝、撤权、原请求重试以及会话元数据。模型综合使用进程内响应夹具。
- WSL 原生文件系统的隔离副本完整离线质量门通过。Python 1629 项（3 项按条件跳过），7 个系统模块 96 项、44.6 秒，分支覆盖率 88%，Node 85/85，Chromium 47/47，模块边界 341 文件、零错误。
- 初轮完整门发现旧消息存储适配的重复响应只保证返回消息编号，新增检查曾直接索引正文。修正后 API 边界 14 项通过，再运行完整门通过。最终浏览器日志记录了本地 uvloop 的资源告警，浏览器断言全部通过。
