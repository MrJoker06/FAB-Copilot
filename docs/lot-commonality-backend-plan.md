# Lot 相关性分析 · 后端改动计划

状态为待评审。基线为 `feat/pe-ee-duty-workspace` 的 `4711c13`。对应[前端计划](lot-commonality-frontend-plan.md)。目标是让页面与值班助手用同一套受控查询取得可核查的跨 lot 统计、成员和加工记录。

## 1. 数据先行

现有 [lot 履历来源](../app/tools/named_queries/data_source.py)按单 lot 返回加工序号、层别、工序、设备、腔室、recipe、加工时间、等待小时数和返工标志，按顺序和时间排序，最多 100 行。[工具描述和绑定](../app/tools/named_queries/binding.py)有既有消费者。多 lot 分析需要新的批量读取或有终止条件的稳定分页。旧接口的 100 行上限不能用于推断某批次从未经过某站。

| 要回答的问题 | 来源至少要提供什么 | 能力不足时的结果 |
| --- | --- | --- |
| 哪些 lot 走过同一路段 | lot、稳定的实际过站顺序、工序、可区分同名工序的层别或站点标识、范围内履历完整性 | 有缺口的相邻记录不能拼成连续路径。局部已证实的命中仍可展示 |
| 哪些 lot 经过同机同腔 | 站点、机台 ID、所属腔室、来源记录标识 | 只知道机台时仍可参与机台统计，腔室标为未知。不同机台的同名腔室分别计算 |
| 同次是否分腔、分别加工多少片 | 来源认可的同次加工标识、各腔室分配记录；若展示片数或 wafer 明细，还须有对应粒度和单位 | 仅凭相同站点或接近的时间不能合并加工事件。可报告已知腔室经历并声明分腔关系或片数未知 |
| 是否使用相同 recipe、返工、等待偏长或集中在一段时间加工 | 有业务口径的 recipe、返工标志、等待时长及单位、加工时间及来源时区 | 返回实测值和范围。没有参考阈值时只展示等待时间分布；缺失值单列 |

实施前核对真实来源可供字段及归属。首版可用受控 SQLite 查询或报表接口实现；具名操作限定 lot 集合、维度、范围和分页。演示来源用合成记录验证接口，真实公司数据接入另记实际验收范围。

## 2. 计算口径

1. **组和分母。** 每组按唯一 lot 计数。成功获准分析的请求中，在允许披露的范围内将未找到或覆盖不足的输入计入未知，并展示原因。每条候选满足“命中 + 确认未命中 + 未知 = 该组纳入分析的唯一 lot 数”。发现无权输入时按授权策略拒绝，不泄露其存在性。跨组重复分别计入各组，合并视图按唯一 lot 去重。历史异常组用于复现对比，正常参考组用于比较暴露比例。
2. **候选。** 以主组中至少两个不同 lot 具有的值作为首版共有项，同时支持单 lot 查履历。一组有 N 个 lot，只有 N 个均确认命中才可称“全部共有”。设备、腔室及 recipe 在对应工序和层别下比较。返工可作为同次过站条件或 lot 级筛选，接口明确回传采用的范围。
3. **路径。** 按实际过站事件生成连续路段。首版建议先比较相邻两站，返回两端及各 lot 的完整上下游供路径视图核对；更长的共同连续段可按共享的相邻关系逐 lot 核实后扩展。多腔分配在有同次加工标识时算一次过站。返工保留为新一次经过。顺序无法确定时声明缺口。
4. **加工时间。** 按工程师选定的加工窗口或明确的分桶宽度汇总命中 lot，返回起止、时区、边界规则和逐条时间。等待按同站、同单位展示。异常发现和加工分别计时。若选“异常前”，对每个 lot 使用其明确截止时间或唯一匹配的截止工序出现次数；存在多个可选过站时请工程师指定，禁止擅取末次并混入事后返工。
5. **结果可追溯。** 命中须有来源记录支撑；确认未命中须有该 lot 在相关范围和维度的完整覆盖。字段缺失、来源截断、部分查询失败分别记录。整次源查询失败返回查询错误。排序以命中数、覆盖情况和稳定键为依据，与根因判断分开；不引入五档评分。

## 3. 前端与助手的共同契约

以下是待评审的操作及字段语义，路径和符号可按现有代码调整。两端先冻结样例响应，再分别实现。

| 操作 | 输入 | 主要输出 |
| --- | --- | --- |
| 创建分析 | 有角色和名称的 lot 分组、选定维度、可选时间范围或截止工序、时区 | 固定到本次查询的 `analysis_ref`、输入回执、各组去重与重叠情况、实际范围、查询时间、来源、覆盖限制、候选列表 |
| 读候选和成员 | 引用、候选 ID、组、命中状态、可选有界筛选与游标 | 每组的三个计数、分母、lot 清单、筛选语义、未知原因、下一页。支持按同一 lot 同时满足“用过 CH-B”及“返工过”筛选，并区分是否限定在同一次过站 |
| 读矩阵、路径和来源记录 | 同一引用、组或 lot、所选站点／候选、游标 | 实际过站、稳定记录引用、顺序、机台、腔室分配数组、recipe、时间、返工和缺失字段。返回能够解释该候选的记录，保留来源时间和粒度 |

页面 API 和 Agent 的具名只读 Tool 共用上述计算及授权路径。Agent 可凭明确的 lot 输入创建分析，也可在聊天请求中携带已有引用做受限回读。通过现有工具装配对本场景开放必要能力，核对默认目录、路由和证据契约的影响。模型不生成 SQL，不从聊天文字重新计算计数。

引用指向有界、可复读的结果版本。输入改变或主动重新查数产生新引用。同一版本的汇总与下钻读取同一份数据。先核对现有结果库对无聊天页面、会话绑定、权限重检、保留期限及容量的支持，再确定复用或补最小存储。页面独立查询应能运行，绑定聊天后沿用现有会话删除语义；引用失效返回明确状态。各读取入口按当前主体重新授权，浏览器传入的计数和源记录不得作为依据。按主体限制组数、lot 数、查询行数、返回页大小、耗时和保存容量；上线前用代表性数据测量并记录选定限额及超限行为。

## 4. 前后端共同验收样例

以下均为人工规定的合成输入和预期，用独立夹具表达。主组 A～H 都在同一层同一站经过 ETCH-07。

| 输入事实 | 应得到的结果 |
| --- | --- |
| A 全部 25 片走 CH-B。B 同次加工的 12 片走 CH-A、13 片走 CH-B。C 确认同次用过两个腔但片数未知。D、E、F 走 CH-B。G 只走 CH-A 且履历完整。H 缺腔室记录 | ETCH-07 为 8/8；CH-B 为命中 6、确认未命中 1、未知 1。三组成员依次为 A～F、G、H。B 的分腔总片数为 25，C 的片数为空 |
| E 在选定范围内两次经过同站同腔，第二次实际返工；其余已知 lot 均未返工 | CH-B 仍是 6 个唯一 lot，E 保留两次记录。“CH-B 且确认返工”清单仅 E |
| A～E 有完整连续的清洗、刻蚀、量测记录。F、G 在刻蚀与量测之间实际经过另一站。H 的该段顺序缺失 | 对“刻蚀后紧接量测”返回 5 命中、2 未命中、1 未知。F、G 的分叉均可在路径明细找到 |
| 人工另建同期异常组 B、J、K；只有 B 经 CH-B，其余两批确认走其他腔 | 主组 CH-B 为 6/8，同期组 1/3。跨组合并后 10 个唯一 lot，CH-B 仍为 6 个 |

另设独立反例：CH-B 证据仅出现在第 101 行、同名腔室属于另一机台、分页中途失败、异常截止后才返工、两个用户互读引用、超过预算、读取失效结果。分别断言成员、来源调用、拒绝结果或缺失原因。以来源事实验证片数，无法定位到 wafer 时禁止推断异常晶圆与某腔对应。
